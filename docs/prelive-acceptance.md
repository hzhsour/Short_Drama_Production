# 真实出片前专项验收

日期：2026-10-17（Australia/Sydney）。检查时 PR #2 已由仓库所有者合并，最新 main 为 `2d0aacbe2a5d1e0f9cb225aab47e1096fcce9b42`；从该版本新建 `codex/prelive-acceptance`。本轮沿用原工程、Skills 和 Remotion，仅修复验收所需缺口。

**本轮没有充值、调用真实生成/TTS API、上传私人素材、设置用户制作预算，或创建可用于 Live 的付费批准文件。** 测试中的费率、用量和权限均为隔离的虚构测试夹具，不是用户的真实报价或授权。

## 一、实际执行通过

### 三种音频模式及最终成片

修复原先源视频始终 `muted`、Ark 未明确设置 `generate_audio` 的行为。现在 `sound_mode` 贯穿结构化剧本、分镜、请求哈希、生成参数、素材元数据、音频清单、时间线与渲染：

| 模式 | 生成音频参数 | 合成行为 |
| --- | --- | --- |
| `model` 保留原声 | `generate_audio=true` | 播放源视频音轨，禁止外部音轨 |
| `dub` 外部配音 | `generate_audio=false` | 源视频静音，播放外部对白/BGM/SFX |
| `silent` 静音 | `generate_audio=false` | 禁止所有声音来源，交付可保留数字静音 AAC |

Live 缺少明确模式、素材/时间线模式冲突、模型原声实际无音轨、非配音模式夹带外部音轨都会拒绝。旧 Mock 的默认 dub 兼容会输出明确警告；不会静默迁移旧 Live 原声。

实际以 FFmpeg 自行生成 440 Hz AAC 视频及 880 Hz PCM 配音，三种模式均经 Remotion、FFmpeg、完整解码质检，并以标准库 FFT 验证：

| 模式 | 440 Hz 频带 RMS | 880 Hz 频带 RMS | 结果 |
| --- | ---: | ---: | --- |
| model | 0.062495 | 0.00000114 | 原声保留，无重复配音 |
| dub | 0.00000130 | 0.115626 | 仅外部配音，无原声叠放 |
| silent | 0 | 0 | 数字静音 |

该声音小样为 160×284、1 秒技术色卡；不验证中文语音或口型质量。规则及复现命令见 [音频模式](audio-modes.md)。

## 二、Mock 通过

### 服务商用量与费用对账

Ark `poll()` 保留官方 `usage.completion_tokens` 及白名单任务/模型/输出规格。分别记录提交前估算、预算预留、返回用量、已核实适用费率算价与最终账单状态，并保留用量观察历史。未知用量/未知提交保守保留预留；后续较小返回不会抹去较高已观察费用。

SQLite 原子汇总 `max(预留, 算价)` 暴露。算价超估算、返回规格与报价范围不符，或达到预算限制时阻止新增付费任务；原已接受任务仍可查询/下载。金额只标为按费率计算、待最终账单，不会写成实际扣款或绝对费用上限。本轮 16 项模拟合约/边界测试通过，未查询真实账单。见 [对账字段与规则](usage-accounting.md)。

### 异步连续推进与本地等待边界

新增可选有界等待：总时限、状态请求次数上限（包括安全重试）、退避间隔和每轮检查点。实际 Mock 序列 queued → running → succeeded 已继续完成下载、剪辑和 MP4 导出；先达到 2 次查询上限返回等待，再次运行复用原 ID，最终每镜提交 1 次、查询 3 次、下载 1 次。

截止不算任务失败，不重提；本地等待截止不会消耗持久失败重试预算，真实 POST 响应不明仍须人工对账。非零 max_jobs 与等待组合被明确拒绝，避免超出用户镜头上限。网络尽量使用剩余时限，正在进行的读取/解码仍可能晚于截止返回，不能称为强制墙钟终止。等待时限不包括之后渲染时间。

有界等待不是永久后台服务。跨 Codex 任务自动唤醒仍需单独部署调度。见 [命令、时间边界与复现](bounded-waiting.md)。

## 三、仍未验证

- 真实 Ark 生成、原声质量、中文对白/口型与 Live 实扣；真实 TTS/声线均未调用。
- 服务商最终账单 API、自动核销及人工复核后的预算释放；本轮没有实现这些功能。
- 用户真实持久卷、备份目标、版本保留、异地复制、灾难恢复和跨任务调度部署；本地副本不等于生产备份。
- GitHub Actions 远端执行：只读查询时运行数为 0。本轮把技术流程改为 e2e 并增加显式 dub 白名单检查，但没有 dispatch/rerun，也不声称远端通过。
- GitHub 公共标准 runner 分钟免费，当前工作流仍使用 cache/artifact；用户存储额度及调度权限未确认，不能保证绝无新增费用，所以本轮不触发。准确手动步骤见 [Actions 审查](prelive-actions.md)。

## 四、Live 前必须完成的配置

1. 用户确认剧本、人物、参考素材权利和明确音频模式；切换模式会改变请求哈希，不能套用旧批准。
2. 用户自行完成模型账号、地区资格、权限和秘密管理注入 `ARK_API_KEY`；重新核实适用报价。本轮不充值、不开通服务。
3. 用户决定单任务、每集、全剧预算及具体付费批准范围；工具不替用户定预算，不创建批准。估算与算价均不能替代最终账单。
4. 配置并确认任务结束后仍保留的受控持久目录，完整保存全部剧集共享账本、运行记录、参考资料、源录音、音视频、字幕、时间线和最终输出。
5. 配置最新一致快照、备份频率、保留版本、异地副本、访问权限和恢复演练。UUID 只能验证身份，不能证明快照最新；旧快照/未知提交先服务端对账。恢复时停止所有共享 worker。完整清单见 [持久化条件](prelive-storage.md)。
6. 如需跨任务自动继续，再部署有限 worker 的外部唤醒；如需远端技术验收，先确认 Actions 权限和缓存/artifact 收费条件。

本轮变更通过独立 PR 交付，保持 main 稳定，等待用户审核，不自动合并。
