# 制作工作流

## 1. 故事开发

从一个可一句话讲清楚的核心设定开始。记录类型、受众、单集长度、季结构、禁区与结局方向。剧本至少说明场景地点/时间、人物、可见动作、对白、声音和场尾钩子；逐场核对人物目标、阻力、选择、后果。

## 2. 人物与视觉连续性

为角色分配稳定 ID（如 `CHAR-001`），把身份事实、关系、性格、外观、服装、禁改项和参考素材分别记下。视觉描述采用稳定特征顺序：年龄范围、脸部轮廓、发型、体态、服装、标志物、色彩和风格。跨镜头更换服装、伤痕或状态时，注明剧情依据。

## 3. 分镜和素材

每个镜头使用 `EP001-SC01-SH001` 格式。分镜 JSON 是可供校验和后续导入时间线的制作清单。将静帧提示词和运动提示词分开；记录对白/音效、连续性引用、审核状态和素材文件。先做关键帧/低成本预览，再制作最终素材。

## 4. AI 视频制作

提示词以镜头需求和角色圣经为依据，注明画幅、动作、镜头运动、环境、光线和时长。不同服务的参数保存在单独配置中，不混进中立的分镜数据。执行前检查账户、计费模式、数据保留和素材许可；未经明确授权不得提交素材或调用 API。

## 5. Remotion 合成

时间、帧数和布局从数据驱动。先确认字体和媒体路径，再做低分辨率短段预览。字幕按镜头 ID 和时间码管理；避免将关键文字放在平台 UI 遮挡区。渲染到 `renders/`，该目录默认忽略于 Git。

## 6. FFmpeg 后期与交付

用 `ffprobe` 记录输入的编码、帧率、画幅、时长和音轨；建立不覆盖原文件的中间产物。分步检查视频/音频时间同步、字幕、黑帧、削波、响度和封装。最终交付记录容器、视频/音频编码、帧率、分辨率、字幕策略和文件哈希。

## 7. 文件命名和追踪

- 剧本：`EP001-script-v001.md`
- 分镜：`EP001-storyboard-v001.json`
- 镜头素材：`EP001-SC01-SH001-video-v001.mp4`
- 参考图：`CHAR-001-front-reference-v001.png`
- 素材说明：同目录 `.md`，包含镜头/角色 ID、来源、生成工具（如有）、提示词版本、授权和审核状态。
